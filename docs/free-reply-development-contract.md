# 自由回复开发复用契约

本文件与[通用架构](free-reply-architecture.md)、[QQ实现](../plugins/qqbot/docs/custom-runtime/free-reply.md)、
[钉钉实现](../plugins/dingtalk/docs/free-reply.md)组成公开开发资料，不依赖其他设计仓库。

## 修改范围

1. 先识别渠道与消息来源，读取对应模块和测试，不把另一个渠道的字段或权限模型直接套用。
2. 优先复用现有状态机、上下文构建与发送接口；不在网关里混入业务专用流程。
3. 不以开放自由回复为理由放开管理员、工具、规则文件或平台身份校验。
4. 不改动无关工作树内容；不重置用户的未读、会话、授权或投递去重记录。
5. 文档描述当前源码，不把预期设计写成已实现，也不把本地测试写成线上验收。

## 最低回归矩阵

| 场景 | 需要证明 |
| --- | --- |
| 普通群消息 | 按参与策略进入未读，不每条立即调用模型 |
| @消息 | 当前消息可立即处理，辅助历史不会变成多条重复回复 |
| 无意义/已处理内容 | 静默，无“没必要回复”的可见解释 |
| 两个群同时来消息 | 队列、历史和回复目标互不串群 |
| 重启与定时器恢复 | 不丢未读，不因旧dueAt永久停止调度 |
| 图片与引用 | 文件真实可读且传入模型；失败不能假称已理解 |
| 历史读取失败 | 不把失败当作没有新消息，不擅自改变读取身份 |
| 发送结果未知 | 保留证据，防止重复发送 |
| 非管理员请求 | 原有工具/管理鉴权仍生效 |

## 检查命令

在仓库根目录执行：

```bash
npm run check:public
npm run check:qqbot
npm run check:dingtalk
```

需要安装依赖时使用各包已有lockfile。QQ的build可能存在本机postbuild同步副作用，
不能为了文档检查或类型检查触发生产同步。钉钉的check会构建本地dist，不等于已部署。

## 发布与运行验收

- 提交源码、测试和文档，并记录commit；推送不等于已部署。
- 部署前确认目标实例、插件目录、运行版本、账号及回滚位置。
- 私有运行数据只在实例中备份，不上传配置、Token、消息日志或截图到公开仓库。
- 真正投递验证需要明确发送目标和授权；没有授权就用只读检查或不发送的测试。
- 完成报告分别列出本地检查、构建、部署、运行和用户验收，不把未验证阶段写成成功。

## 公开边界

自有必要设计必须随本仓发布；不能把它迁入组织私仓后只留下失效跳转。
官方上游、开源依赖与赞助信息不必迁为个人项目，但必须是公开来源。
新增GitHub依赖/参考需先验证可匿名访问，再更新公开来源检查的允许列表。
不要复制组织私有内容、内部运行配置或聊天证据；公开说明应依据本仓公开代码重新维护。
历史提交不做强制改写；公开入口以当前main为准。
